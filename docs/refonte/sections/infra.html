Séquence de déploiement — vague 1 des correctifs

Issue de l'audit croisé du 21/08. À dérouler dans cet ordre : chaque étape suppose la précédente.

#ÉtapePourquoi cet ordre
1Déployer le code de la branche correctifs/audit-croise-20260821 Le VPS sert encore le code d'avant vague 1, shell=True compris.
2backend/venv/bin/python backend/scripts/rotate_encryption_key.py --verify-only Contrôle sans écriture : dit combien de jetons Git sont encore en clair.
3backend/venv/bin/python backend/scripts/rotate_encryption_key.py --encrypt-plaintext --apply Obligatoire avant tout déploiement BUILD. Sans cela, un projet dont le jeton Git est resté en clair cesse de déployer — arrêt net et journalisé, pas de corruption, mais le service s'arrête.
4Redémarrer digital-humans-backend et -worker Compter 40 à 50 s de rechargement ChromaDB avant de tester.
5Vérifier que /api/agent-tester/org/query répond 401 sans jeton C'est la preuve que le correctif applicatif est actif.
6Retirer le blocage nginx location ~ ^/api/agent-tester Jamais avant l'étape 5. Ce 403 est la seule protection contre l'exécution de commandes tant que le code corrigé n'est pas déployé.

Point de vigilance. Les tests ne sont pas isolés de la base de production : lancer pytest sur le VPS sans DATABASE_URL dédiée tente un DROP TABLE sur les données réelles. Le 21/08, seule la vue v_deos_sections du comité l'a empêché.
